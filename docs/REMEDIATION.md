## Важные изменения совместимости

1. Production теперь **не запускается** с прежними небезопасными значениями по умолчанию. Заполнить окружение по `.env.production.example`.
2. `Submission.objects.get(student=…, assignment=…)` больше не означает «единственная сдача»: используйте последнюю версию либо `latest_attempts()`. Встроенные views/Admin обновлены.
3. Проверка оценивается относительно **максимума на момент отправки**, а не будущей отредактированной карточки задания. Старые дедлайны тоже фиксируются.
4. Admin для сдач/feedback теперь readonly. Редактирование проверки — через основной интерфейс с version tokens и журналом.
5. Файлы больше не публичны; старый `/media/` intentionally возвращает 404. Не обходить эту защиту alias/CDN.
6. Миграция `0002` сохраняет доступные исходные записи, но не может восстановить ранее перезаписанные ответы. Неверные старые баллы требуют ручного решения преподавателя; миграция не подменяет их «правильными» числами.
7. Миграция необратима после введения множественных попыток. Нужен согласованный предмиграционный backup БД/media и план rollback через восстановление, не `migrate 0001`.

## Выполненные локальные проверки

- Регрессионный набор на SQLite / Python 3.11.2: 96 обнаруженных тестов, 93 выполнены успешно; два PostgreSQL-only и один opt-in browser тест пропущены в обычном запуске.
- Браузерный тест отдельно выполнен на Chromium 153: реальный HTTP workflow от входа до пересдачи; на пяти страницах нет axe violations, отсутствующих ARIA help targets и переполнения документа при 320px.
- Покрытие прикладного кода со счётом ветвей — **92%**; migrations/tests/test settings/WSGI scaffolding исключены из метрики.
- Ruff check/format, `makemigrations --check --dry-run`, production deployment checks проходят. В deployment checks только W005/W021 намеренно исключены согласно доменной политике выше.
- Миграция с исходной схемы проверена на отдельной временной БД: ID/ответ/файл/время/feedback сохраняются; некорректная оценка не изменяется и блокирует upgrade.

В локальной среде нет Docker/PostgreSQL/Python 3.12; загрузка их бинарных компонентов ограничена сетью. Соответствующие реальные проверки вынесены в отдельные CI jobs, их результат нужно смотреть в PR. Параметры настоящего production, backup/restore и настройки GitHub branch protection в эту проверку не входят.
