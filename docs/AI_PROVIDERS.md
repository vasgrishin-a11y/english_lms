# ИИ-помощник на локальной модели: Ollama и LM Studio

Помощник преподавателя (`/teacher/ai/`) собирает из материала структуру курса: класс (Block) →
главы (Chapter) → темы (Topic) → задания (Assignment) → вопросы теста или карточки-тренажёра.
Логика промпта соответствует моделям `lms/models.py` и `lms/ai.py`: допустимы типы заданий
`text`, `file`, `audio`, `mixed`, `quiz`, `flashcards`, `material`, навыки `grammar`,
`vocabulary`, `listening`, `speaking`, `writing`, `reading` и виды вопросов из схемы помощника.
Разбор выполняет модель, запущенная **на своём железе**: Ollama или LM Studio. Ключей, аккаунтов,
карт и облака нет — значит, нет и оплаты, нет зависимости от доступности сервиса из России и
нет передачи материалов третьей стороне.

## Как промпт работает с неизвестным учеником

Во время генерации конкретный ученик заранее неизвестен: помощник не получает имя, возраст,
родной язык, биографию, историю попыток, ошибки или оценки. Поэтому промпт требует создавать
универсальное переиспользуемое задание для аудитории, которая описана только явно переданными
параметрами — например, уровнем CEFR, темой, навыком, возрастом/группой и целью. Если параметры
не указаны, модель не должна выдумывать профиль и обращается к ученику нейтрально.

ИИ не назначает материал и не добавляет в задание имена или идентификаторы: импорт создаёт только
черновики. После проверки преподаватель публикует задание и назначает его группе или отдельным
ученикам средствами LMS. Проверка этого правила действует и для генерации нового материала,
и для правки существующего задания — в правку передаётся структура курса, но не работы учеников
и не их персональные данные.

### Материал, необходимый для ответа

Задание должно быть самодостаточным для ученика. Если оно требует прочитать текст, посмотреть
картинку, прослушать аудио или открыть файл, промпт требует либо встроить полный материал в
условие задания, либо использовать вложение, которое действительно доступно ученику. Исходный
файл, загруженный на страницу ИИ-помощника, используется как источник для разбора и не
становится вложением задания автоматически. Поэтому фраза «прочитайте текст и ответьте на
вопросы» допустима только вместе с самим текстом или доступным вложением; иначе помощник должен
создать самодостаточный материал или выбрать другой тип задания.

## Проверка и правка до импорта

После генерации `/teacher/ai/` показывает подробный предпросмотр: условия заданий, навыки,
вопросы и варианты ответов с ключами, пояснения и карточки. Преподаватель может отправить
инструкцию «что изменить» для текущей версии. ИИ возвращает полную обновлённую структуру, но
она хранится только в сессии и не записывается в курс. Кнопка «Импортировать черновиками»
создаёт записи только после того, как преподаватель проверил финальный предпросмотр.

```dotenv
LMS_AI_ENABLED=1
LMS_AI_PROVIDER=ollama           # ollama | lmstudio | своё имя для OpenAI-совместимого шлюза
LMS_AI_LOCAL=1                   # «локальная модель включена»: снимает требование ключа
LMS_AI_MODEL=qwen3-vl:8b         # vision-модель, читает фото страниц
LMS_AI_TIMEOUT=120
```

Без `LMS_AI_LOCAL=1` (или ключа у своего шлюза) помощник не выключается: он разбирает материал
офлайн-эвристиками — DOCX, XLSX, PDF, TXT/MD/CSV и структурированный текст. Это по-прежнему
рабочий режим, просто без ИИ.

## Почему остались только локальные модели

- **Бесплатно навсегда.** Нет тарифов, квот и пробных периодов: модель живёт на вашем сервере.
- **Работает из РФ без VPN.** Никаких региональных ограничений и зарубежных аккаунтов.
- **Фото и вложения.** Vision-модели читают снимок страницы учебника и переносят её в структуру
  курса — главный сценарий помощника.
- **Данные не уходят наружу.** Материалы преподавателя не покидают контур — это самый простой
  вариант и с точки зрения 152-ФЗ.

Облачные адаптеры (**Gemini**, **GigaChat**, Yandex AI Studio, ProxyAPI, VseGPT, AITUNNEL,
OpenRouter, DeepSeek, Qwen) из поставки удалены: им нужны ключ, аккаунт и квота, а Gemini API
из России недоступен без VPN и зарубежного аккаунта. Если облако когда-нибудь понадобится,
его добавляют как **свой OpenAI-совместимый шлюз** — см. последний раздел.

## Ollama — рекомендуемый вариант

1. Установите Ollama на сервер, где крутится приложение (или на отдельную машину в той же сети):

   ```bash
   curl -fsSL https://ollama.com/install.sh | sh
   ```

2. Скачайте vision-модель. Значение по умолчанию в проекте — `qwen3-vl:8b`:

   ```bash
   ollama pull qwen3-vl:8b
   ollama list          # покажет имя модели: подставьте его в LMS_AI_MODEL
   ollama serve         # слушает http://localhost:11434, API — /v1
   ```

3. Включите помощник: `LMS_AI_PROVIDER=ollama`, `LMS_AI_LOCAL=1`, `LMS_AI_MODEL=<имя модели>`.

Ключ не нужен: Ollama отдаёт OpenAI-совместимый API на `http://localhost:11434/v1`, и помощник
считает его локальным, если выставлен `LMS_AI_LOCAL=1`.

### Какие модели брать

| Модель | Ориентир по железу | Сильная сторона |
| --- | --- | --- |
| `qwen3-vl:8b` (по умолчанию) | ~8 ГБ видеопамяти или столько же RAM | лучшее распознавание текста на фото, разбор таблиц и схем |
| `qwen2.5vl:7b` | ~8 ГБ | проверенный предшественник, хорошо читает страницы |
| `gemma3:4b` | ~3 ГБ | слабое железо: ноутбук или школьная машина |
| `minicpm-v` | ~6 ГБ | аккуратное OCR, меньше галлюцинаций на мелком шрифте |
| `llava` | ~5 ГБ | запасной вариант, если новых моделей нет в реестре |

Проверенные сочетания: **фото страниц и тесты** — `qwen3-vl:8b`; **только текст** (планы,
конспекты) — любая текстовая модель, например `qwen3:8b`, она быстрее.

`llama3.2-vision` в свежих версиях Ollama не запускается (ошибка `unknown model architecture:
mllama`) — берите модели из таблицы выше.

### Ресурсы и скорость

- Модель уровня 7–8B на CPU отвечает десятки секунд на запрос: разбор фото может занять
  пару минут. Держите `LMS_AI_TIMEOUT` (по умолчанию 60 с) меньше, чем `proxy_read_timeout`
  у Nginx, иначе пользователь увидит таймаут прокси вместо ответа помощника.
- На видеокарте с 8 ГБ и больше разбор укладывается в десятки секунд.
- Первый запрос всегда медленнее: модель загружается в память, дальше она остаётся горячей.

## LM Studio — если нужен настольный вариант

1. Установите LM Studio, скачайте vision-модель (те же `qwen3-vl-8b` / `gemma-3-4b`).
2. Вкладка **Developer → Start Server**: сервер поднимется на `http://localhost:1234/v1`.
3. Скопируйте идентификатор загруженной модели из списка и задайте:

   ```dotenv
   LMS_AI_PROVIDER=lmstudio
   LMS_AI_LOCAL=1
   LMS_AI_MODEL=qwen/qwen3-vl-8b
   ```

LM Studio удобен для проверки материала вручную с рабочего ноутбука; для постоянной работы на
сервере берите Ollama.

## Свой OpenAI-совместимый шлюз

Любое незнакомое значение `LMS_AI_PROVIDER` считается OpenAI-совместимым шлюзом: достаточно
указать адрес и ключ. Так подключают и корпоративный прокси, и облачный сервис, если он когда-то
понадобится.

```dotenv
LMS_AI_PROVIDER=my-gateway
LMS_AI_ENDPOINT=https://ai.example.ru/v1
LMS_AI_API_KEY=<ключ>
LMS_AI_MODEL=<модель>
```

Если у модели нет локального сервера по HTTPS, оставьте `LMS_AI_VERIFY_SSL=1`. Для внутреннего
сертификата укажите путь в `LMS_AI_CA_BUNDLE`; отключать проверку TLS (`LMS_AI_VERIFY_SSL=0`)
стоит только на время отладки.

## Как помощник работает с вложениями

| Материал | Что происходит |
| --- | --- |
| Фото страницы (PNG, JPG, WEBP, GIF, BMP) | Кодируется в `data:`-строку и уходит в модель как `image_url` — vision-модель видит изображение |
| DOCX, XLSX, PDF, TXT, MD, CSV, JSON | Текст извлекается офлайн (`zipfile`, встроенные парсеры) и добавляется к промпту |
| Видео и аудио | Не отправляются: локальная модель их не читает. Помощник честно пишет об этом в отчёте |
| Ничего из перечисленного, но есть текст | Работает офлайн-разбор структуры |

Провайдер объявляет свои возможности сам (`LMS_AI_UPLOAD_KINDS=image,none` — что отправлять
вложением), поэтому в интерфейсе нет обещаний, которых модель не выполнит.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LMS_AI_ENABLED` | `1` | Окно помощника; `0` выключает его целиком |
| `LMS_AI_PROVIDER` | `ollama` | `ollama`, `lmstudio` или своё имя OpenAI-совместимого шлюза |
| `LMS_AI_LOCAL` | `0` | `1` — модель работает локально: ключ не требуется, режим «онлайн» включается без него |
| `LMS_AI_ENDPOINT` | адрес пресета | Переопределение базового адреса API (`http://localhost:11434/v1`) |
| `LMS_AI_MODEL` | `qwen3-vl:8b` | Имя модели из `ollama list` или идентификатор в LM Studio |
| `LMS_AI_API_KEY` | пусто | Нужен только для своего шлюза с авторизацией |
| `LMS_AI_JSON_MODE` | `0` для локальных | `response_format=json_object`: поддерживают не все модели — при ошибке 400 помощник подскажет поставить `0` |
| `LMS_AI_TIMEOUT` | `60` | Таймаут запроса к модели в секундах (для локальных моделей разумно 120) |
| `LMS_AI_CA_BUNDLE` | пусто | Путь к корневому сертификату внутреннего шлюза |
| `LMS_AI_VERIFY_SSL` | `1` | `0` — отключить проверку TLS (только для отладки) |
| `LMS_AI_UPLOAD_KINDS` | `image` | Что отправлять вложением: `image`, `none` |
| `LMS_AI_MAX_*` | см. `.env.production.example` | Лимиты структуры: блоки, темы, задания, вопросы, карточки, длина текста, размер файла |

## Проверка настроек

```bash
python manage.py ai_check            # режим, провайдер, модель, адрес, вложения — без сети
python manage.py ai_check --live     # один пробный материал и счётчики черновика
```

`ai_check` без `--live` ничего не отправляет и ничего не создаёт: это безопасный способ
убедиться, что площадка видит переменные. `--live` делает ровно один запрос к модели, черновики
не создаёт и печатает понятную причину, если сервер модели не запущен.

Если помощник отвечает «Нет связи с моделью…», проверьте по порядку: запущен ли `ollama serve`,
совпадает ли адрес с `LMS_AI_ENDPOINT`, скачана ли модель (`ollama list`) и совпадает ли её имя
с `LMS_AI_MODEL`.

## Ограничения, о которых нужно знать

- **Проверка человеком обязательна.** Помощник создаёт только черновики; формулировки, уровни и
  ключи к тестам просматривает преподаватель.
- **Видео и аудио.** Локальные vision-модели их не читают: помощник разберёт текст задания, а
  файл останется вложением задания, если преподаватель добавит его вручную.
- **Железо.** Модель уровня 7–8B требует около 8 ГБ памяти и заметно нагружает машину при
  разборе фото; для слабого железа выбирайте модель поменьше.
- **Журнал.** В лог `lms.ai` пишутся только счётчики и коды ошибок: содержимое файлов и работ
  учеников не логируется.

## Что менять в коде при добавлении провайдера

Обычно — ничего: добавьте пресет в словарь `PROVIDERS` (`lms/ai.py`) либо задайте
`LMS_AI_PROVIDER` + `LMS_AI_ENDPOINT`. Если у провайдера собственный протокол, нужен новый
`kind` — как это было у Gemini и GigaChat до перехода на локальные модели. Тесты живут в
`lms/tests/test_ai.py` и работают без сети: транспорт подменяется классом `FakeTransport`.
