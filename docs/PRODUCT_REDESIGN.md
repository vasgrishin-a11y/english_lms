## 0. TL;DR

1. **Главная структурная проблема не в цветах, а в том, что продукт разрезан на два несвязанных мира.** Учебный контент (блоки/темы/задания) живёт в Django Admin, а работа учителя с проверкой — в самописных страницах `lms/templates`. Учитель физически не может создать задание: `/admin/` для роли `teacher` отдаёт 302 (нет `is_staff`), а в LMS-интерфейсе CRUD курса нет вовсе. Пункт 1 и пункт 4 вашего запроса упираются именно сюда.
2. **Предлагаю единый «Teacher Console»** — один серверно-рендеренный shell с переключателем пространств `Проверка · Курс · Аналитика · Ученики · Настройки`, общим левым «рельсом» (карта курса / фильтры очереди) и общей дизайн-системой. Django Admin остаётся для системных операций (пользователи, права, журнал аудита) и встраивается ссылкой в тот же shell — а не наоборот.
3. **Визуал** — пастельный минимализм на CSS-переменных: тёплый off-white canvas, шалфейный или перивинкловый акцент, пастель только как **фон и тон**, текст и кнопки — глубокими тонами (иначе WCAG AA не проходит: белый на пастели `#A8C0A0` = **1.96:1**, провал; см. Приложение A с просчитанными контрастами).
4. **Иерархия** — 4 дополняющих представления: дерево-карта курса (учитель), «дорожная карта» с прогрессом (ученик), матрица-журнал «ученики × задания» (учитель), breadcrumb + CEFR-бейджи везде. Плюс исправление реального бага восприятия: сейчас пагинация **режет блоки и темы пополам** (`views.py:75-84` группирует уже после `Paginator`).
5. **Ценность для учителя** — speed-grading (переход к следующей работе, клавиши `J/K/G/C/R` как в Canvas SpeedGrader), рубрики, банк комментариев, автопроверяемые упражнения (MCQ / matching / gap-fill), квизлеты-карточки с интервальным повторением (SM-2), аудио-плеер и запись в браузере, планировщик публикации, аналитика, экспорт журнала, уведомления (поле `Profile.telegram` уже есть и простаивает).
6. **AI-помощник** — провайдер-агностичный адаптер (OpenAI / Anthropic / Gemini / OpenRouter / локальный Ollama / **mock для CI**), загрузка PDF·DOCX·TXT·фото страницы учебника → извлечение текста (для фото — vision/OCR провайдера) → структурированный черновик (блок → темы → задания → квиз → карточки → рубрика) → **редактирование учителем → публикация человеком**. AI ничего не публикует сам, всё логируется, лимиты по токенам и стоимости, fail-closed без ключа.
7. **Ученик** — домашняя страница «Продолжить / Сегодня дедлайн / Прогресс», черновик с автосохранением (не ломая неизменяемость попыток), запись аудио в браузере, мгновенная автопроверка тестов, тренажёр карточек, мягкая геймификация, мобильная вёрстка.
8. **Ничего не ломаем**: версионирование попыток, optimistic locking (409), приватные файлы, лимиты загрузки, django-axes, бюджет SQL-запросов, axe-проверки и покрытие ≥80% — это актив, а не препятствие. Раздел 7 честно описывает, что именно в тестах придётся обновить вместе с разметкой.

**Что мне нужно от вас перед стартом** — 6 решений (раздел 8, задам отдельным виджетом) и ответы на второстепенные вопросы.

### 2.2 Что сильно и должно быть сохранено

- **Неизменяемые попытки** с версией, снапшотом `max_points` и `deadline` (`models.py:161-300`) — редкая для MVP зрелость.
- **Optimistic locking**: 409 на устаревшую форму ученика и учителя, `review_revision`, блокировка строки ученика (`services.py`).
- **Приватные файлы**: `/files/…` с авторизацией, `attachment`, `no-store`, `nosniff`, валидация сигнатур и реального аудио через Mutagen (`views.py:256-292`, `validators.py`).
- **Лимиты**: размер, квота, частота отправок, `UploadLimitMiddleware` (413).
- **Доступность**: skip-link, `aria-describedby`, именованная прокручиваемая таблица, axe-проверки 5 страниц, отсутствие overflow на 320px.
- **Дисциплина запросов**: бюджет ≤6 SQL на каталог и очередь (`test_queries.py`).

Всё это — фундамент, на который новый UI должен «сесть», а не переписать.

### 3.2 Пять принципов, которые я вынес из бенчмарков

1. **Одна рабочая поверхность.** Учитель не должен выходить из продукта, чтобы изменить курс. Всё — в одном shell с переключением пространств.
2. **Скорость проверки = главная метрика.** Меньше кликов на работу: очередь → split-view → оценка → `J` → следующая.
3. **Мгновенная обратная связь там, где она возможна без человека.** Автопроверяемые упражнения разгружают учителя и дают ученику ответ за секунды.
4. **Путь виден.** Прогресс по блоку/теме/навыку должен быть на каждом экране, а не в отдельном отчёте.
5. **AI — черновик, человек — автор.** Никакой автопубликации, обязательный редактор, аудит и лимиты.

## 4. Предлагаемое решение

### 4.3 Понятная иерархия: тема → блоки → задачи (ваш пункт 5, G3, G4)

Четыре представления одного дерева, каждое на своём месте:

**(a) Карта курса — дерево в левом рельсе учителя** (основной навигационный инструмент):

```
📚 Карта курса                                    A2 · B1 · все
▾ 🟦 A2 — Базовый курс                    ▮▮▮▮▮▯▯ 68%  6 заданий
   ▾ 📘 Present Simple vs Continuous      ▮▮▮▮▮▮▮ 100%  2
      ▪ Раскройте скобки …                 40 б · 3 сдано · 2 проверено
      ▪ Опишите свою обычную субботу       100 б · ⏳ 2 ждут проверки
   ▸ 📗 Vocabulary: Travel                 ▮▮▯▯▯▯▯ 25%  1
   ▸ 📕 Speaking & Listening               ▮▯▯▯▯▯▯  0%  1
▸ 🟨 B1 — Продолжающий                     ▮▮▯▯▯▯▯ 30%  2
[ + Блок ]  [ + Тема ]  [ + Задание ]  [ Импорт из файла (AI) ]
```
Каждый узел: иконка типа, прогресс, счётчики («сколько сдано / ждёт проверки / проверено»), контекстное меню (создать внутри, дублировать, переместить, скрыть, предпросмотр). Перетаскивание для порядка + клавиатурная альтернатива. Ленивая загрузка через `htmx`, чтобы не терять бюджет запросов.

**(b) Дорожная карта ученика** — вертикальный «путь» с узлами (как skill path), где видно пройденное, текущее и заблокированное/предстоящее, плюс проценты и ближайшие дедлайны. Для детей/подростков — основной экран; для взрослых — переключаемый вид «список».

**(c) Матрица журнала** (учитель, пространство «Аналитика»): ученики по строкам, задания по колонкам, в ячейке — балл/статус/число попыток. Липкие заголовки, сортировка, фильтр по теме, экспорт CSV, цветовая подсказка + обязательный символ/текст (не только цвет).

**(d) Breadcrumb + CEFR-бейджи** на каждом экране: `A2 — Базовый курс › Present Simple vs Continuous › Опишите свою обычную субботу › Попытка 2`. Это дешёвый и очень эффективный способ убрать «где я?».

**Исправление G4 (пагинация режет иерархию).** Варианты:
1. Пагинировать **по блокам/темам**, а не по заданиям (группировка до среза) — рекомендую, сохраняет целостность;
2. «Показать весь курс деревом» с ленивой загрузкой узлов — лучший UX при ≤500 заданий;
3. Оставить как есть и лишь добавить breadcrumb — не решает проблему.
Рекомендую 1+2: дерево как основной вид, плоский список с пагинацией — как запасной/поисковый.

**Дополнительно: теги навыков** (`Skill`: Grammar, Vocabulary, Listening, Speaking, Writing, Reading + CEFR-уровень). Они дают третью ось иерархии (помимо структуры курса) и позволяют строить радар прогресса ученика и аналитику «какая навыковая зона проваливается».

### 4.5 AI-помощник создания заданий (ваш пункт 4)

**Пользовательские сценарии (пресеты вместо «пустого чата» — как в MagicSchool):**

| Пресет | Вход | Выход (черновик) |
|---|---|---|
| «Собрать блок из файла» | PDF/DOCX/фото страницы учебника + уровень (A2) + число тем | `Block` + 3–5 `Topic` + описания + порядок |
| «Сделать задание» | материал + тема + тип ответа + баллы + дедлайн | `Assignment` (условие, критерии, max_points, тип) |
| «Квиз по тексту» | текст/файл | 5–15 MCQ/gap-fill с правильными ответами и объяснениями |
| «Квизлет/карточки» | текст или список слов | `FlashcardDeck` + 20–40 карточек (перевод, пример, IPA) |
| «Рубрика» | описание задания | `Rubric` с критериями и уровнями 0–5 |
| «Упростить/усложнить текст» | текст + целевой CEFR | переработанный текст + дифф |
| «Проверить моё задание» | черновик учителя | замечания: однозначность, соответствие уровню, типовые ошибки, анти-AI-формулировки |
| «Диктант/аудирование» | аудиофайл | скрипт + пропуски + вопросы (только если аудио ваше/лицензированное) |

**Архитектура** (провайдер-агностичная, fail-closed):

```
[UI: панель AI в редакторе / «Импорт из файла» в дереве]
        │  POST (multipart: файл + пресет + параметры)
        ▼
[AiJob] ── валидация: роль teacher/staff, размер, тип, лимит jobs/час, бюджет токенов
        │
        ▼
[Ingest]  pdf → pypdf · docx → zipfile+xml · txt/md/csv → utf-8 · image → провайдер-vision/OCR
        │  → извлечённый текст ограничен N символов, PII-фильтр (regex: email/телефон/имена учеников)
        ▼
[Provider adapter]  GigaChat(Сбер, по умолчанию) | Yandex AI Studio | OpenAI-совместимые
                    (ProxyAPI · VseGPT · AITUNNEL · OpenRouter · DeepSeek · Qwen · Ollama)
                    | Gemini | Mock(для CI и офлайн-демо)
        │  JSON-schema контракт + retry/timeout + учёт токенов и стоимости
        ▼
[AiDraft]  структурный черновик (blocks/topics/assignments/questions/cards/rubric) + исходный промпт + версия модели
        │
        ▼
[Редактор черновика]  дерево слева, предпросмотр справа, diff, «взять/изменить/отклонить» по каждому узлу
        │
        ▼
[Публикация ЧЕЛОВЕКОМ] → обычные модели курса + AiAuditLog (кто, когда, что сгенерировано, что опубликовано)
```

**Принципы безопасности и этики (обязательные):**
1. AI **никогда** не пишет в `Block/Topic/Assignment` напрямую — только в `AiDraft`. Публикация — явное действие человека.
2. Функция отключается env-флагом (`LMS_AI_ENABLED=0`); без ключа UI показывает «Офлайн-разбор» и продолжает работать локально, а не падает.
3. **Данные учеников по умолчанию не отправляются.** Сценарий «AI-разбор ответа ученика» — отдельный opt-in с обезличиванием (без имени, без файлов ученика, только текст) и явным уведомлением в интерфейсе.
4. Лимиты: jobs в час на пользователя, максимум символов входа, максимум токенов выхода, месячный бюджет стоимости, таймаут, повтор только идемпотентный.
5. Полный аудит: промпт, параметры, модель, ответ, стоимость, кто опубликовал что.
6. Загруженные файлы хранятся в том же приватном контуре (не публичный `/media/`), удаляются после обработки по политике retention.
7. Никакого выполнения сгенерированного кода/HTML: черновик — только данные, рендер через существующие экранирующие шаблоны.

**Зависимости и CI.** Предлагаю минимум: `httpx` (HTTP-клиент, pinned с хешами) + `pypdf` (текст из PDF). Не тянуть тяжёлые SDK. Для тестов — `MockProvider` (детерминированный, без сети) + отдельный opt-in job с реальным провайдером по секрету. `pip-audit`/`bandit`/`pip-compile --generate-hashes` остаются зелёными.

**Стоимость (ориентир на 1 загрузку учебника, ~10 стр. ≈ 25k токенов входа, ~4k выхода):** доли цента–центы у массовых моделей; при 200 генерациях в месяц это единицы долларов. Точные цифры зависят от выбранного провайдера — скажите, каким ключом располагаете.

### 4.6 Ученик: проще, интереснее, без friction (ваш пункт 7, G6, G7, G10)

**Новая домашняя страница ученика** вместо «списка всего»:

```
Привет, Анна 👋                       Ваш прогресс: A2 ▮▮▮▮▮▯▯ 68%
┌───────────────────────────┐  ┌──────────────────────────────┐
│ ▶ Продолжить              │  │ ⏰ Сегодня и завтра            │
│   Опишите свою субботу    │  │  · Деловое письмо — через 2 дн.│
│   черновик сохранён 12 мин│  │  · Аудио-ответ — через 6 дн.   │
│   [ Продолжить ]          │  │  ⚠ Тест Travel — просрочен    │
└───────────────────────────┘  └──────────────────────────────┘
┌ 🔤 Тренажёр слов: 12 карточек готовы к повтору  [5 минут] ┐
┌ 📊 Оценки: Present Simple 38/40 · Суббота — на доработке ┐
[ Дорожная карта ]  [ Все задания ]  [ Тренажёры ]  [ Оценки ]
```

**Ключевые улучшения:**
1. **Черновик с автосохранением** — отдельная сущность `AnswerDraft` (localStorage + сервер), не трогающая неизменяемость `Submission`. Убирает самую болезненную потерю текста при 409/429.
2. **Карточка задания понятным языком**: что сделать → в каком формате → объём → критерии/рубрика → сколько баллов → дедлайн с обратным отсчётом → чек-лист перед отправкой. Сейчас требования «спрятаны» в свободном тексте описания.
3. **Мгновенная обратная связь** в автопроверяемых упражнениях: результат сразу, разбор ошибок, «попробовать ещё» (попытка тренировочная, не оцениваемая).
4. **Запись аудио в браузере** (MediaRecorder) + предпрослушивание перед отправкой. *Внимание:* потребуется добавить формат (webm/opus или конвертация в wav) в `ALLOWED_FILE_EXTENSIONS` и в валидатор Mutagen — это изменение политики файлов, спросите/согласуйте.
5. **Тренажёр карточек** (SM-2): 5–10 минут в день, статистика «знаю/учу», озвучка через `speechSynthesis` без внешних сервисов.
6. **Мягкая геймификация** (опционально и отключаемо): прогресс-путь, серии дней, значки за блоки, XP. Без лидербордов по умолчанию — они демотивируют слабых и создают давление.
7. **Понятные уведомления**: «Ваша работа проверена: 38/40, комментарий учителя» — в приложении + email/Telegram.
8. **Мобильность**: один столбец, крупные цели касания (≥44px), нижняя таб-навигация на узких экранах, никакого горизонтального скролла (уже контролируется тестом на 320px).
9. **Онбординг** 3 шага при первом входе + контекстные подсказки («как отправить первую работу»).
10. **Язык ошибок по-человечески**: вместо «Конфликт версии» — «Кто-то (или вы в другой вкладке) уже отправил ответ. Откройте свежую страницу — ваш текст сохранился в черновике».

Данные: 3 блока → 6 тем → 8 заданий всех типов (`text`, `file`, `audio`, `mixed`, `quiz` + черновик задания), тест из 4 вопросов с автопроверкой, 2 набора карточек (12 карточек), работы в состояниях «проверена / на доработку / в очереди», автопроверенные тесты 10/10 и 8/10, черновик ответа с автосохранением, повторения карточек по SM-2, банк из 4 комментариев. Локальные `db.sqlite3`, `media/` и `.env` — в `.gitignore`.

Что посмотреть:

- **Ученик** (`anna`): `/my/` (продолжить работу, сроки, прогресс, тренажёр, последние оценки) · `/assignments/` (карта курса и список, поиск) · `/assignments/<id>/` (тест с мгновенной проверкой, черновик, история попыток, запись аудио) · `/trainer/` и `/trainer/<id>/` (карточки, оценки «again/hard/good/easy») · `/upcoming/` · `/grades/`.
- **Преподаватель** (`teacher`): `/teacher/` (консоль: очередь, черновики, обзор) · `/teacher/review/` (FIFO-очередь, хоткеи) · `/teacher/review/<id>/` (проверка, банк комментариев, «следующая работа») · `/teacher/curriculum/` (дерево курса, CRUD, перемещение) · `/teacher/students/` и `/teacher/students/<id>/` · `/teacher/analytics/` (журнал-матрица + CSV) · `/teacher/settings/`.
- **Инвариант прав**: `/admin/` доступен только superuser; у роли `teacher` — 302 (проверяется тестом).
