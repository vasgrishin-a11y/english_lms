# English LMS

Небольшая LMS на Django 5.2 LTS / Python 3.12: задания, неизменяемые попытки учеников, проверка преподавателем, история решений и защищённые файлы. PostgreSQL обязателен для production; SQLite разрешён только в явно включённой локальной разработке и тестах.

## Локальный запуск

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install --require-hashes -r requirements-dev.txt
cp .env.example .env
# Только при первоначальном создании .env; не выводит ключ в терминал.
python -c 'import secrets; from pathlib import Path; p=Path(".env"); p.write_text(p.read_text().replace("DJANGO_SECRET_KEY=", "DJANGO_SECRET_KEY=" + secrets.token_urlsafe(64), 1))'
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 0.0.0.0:8000
```

Открыть `/admin/`, создать блок → тему → задание и учётные записи. Для внешнего dev-preview добавьте **его точный hostname** в `DJANGO_ALLOWED_HOSTS`, а HTTPS origin — в `DJANGO_CSRF_TRUSTED_ORIGINS`. Не используйте `DEBUG=True` на публичном сервере с реальными данными.

### Пошаговая проверка пунктов и запись голоса

- В задании-тесте ученик отвечает на каждый пункт и нажимает «Принять»: сразу видит ✓ или ✗
  и сколько попыток осталось (по умолчанию 3, преподаватель задаёт 1–5 в настройках задания).
  Верный ответ с любой попытки даёт полный балл; после последней неудачной попытки
  показываются правильный ответ и пояснение. Прогресс сохраняется на сервере.
- Типы пунктов «Свободный ответ» и «Голосовой ответ» проверяет преподаватель: в разборе
  видны все попытки ученика по каждому пункту (включая неверные), плеер записи и поле баллов;
  итог складывается автоматически. Матрица «ученик × пункт» — кнопка «Результаты по пунктам».
- Лимит записи задаётся в секундах или минутах (10 с – 10 мин) для аудио-заданий и для
  каждого голосового пункта. Браузер показывает обратный отсчёт, предупреждает за 10 секунд
  и останавливает запись сам; сервер дополнительно проверяет длительность файла.
  Запись кодируется в WAV 16 кГц моно (~1,9 МБ/мин). Перезаписывать можно без ограничений.
- «Режим контрольной» в настройках задания: одна попытка на пункт, ✓/✗, правильные ответы
  и пояснения ученик видит только после ответа на все пункты.
- «Результаты по пунктам» выгружаются в XLSX: строка на ученика, столбец на пункт
  (✓/✗, баллы, номер попытки), внизу — доля верных по каждому пункту.
- Микрофон в браузере доступен только по HTTPS (или на localhost) — на стенде нужен TLS.

### Демо-данные (осмотр интерфейса без ручного наполнения)

```bash
python manage.py seed_demo                    # случайный пароль печатается один раз
python manage.py seed_demo --password '...'   # либо задать свой пароль
```

Команда создаёт курс (3 блока → 6 тем → 8 заданий всех типов, включая задания-тренажёры с карточками), тест с автопроверкой, работы в разных состояниях, черновик ответа и банк комментариев. Логины: `admin`, `teacher`, ученики `anna`, `maxim`, `sofia`. Запуск идемпотентен и разрешён только при `DEBUG=True` (иначе — явный `--force`); пароль в коде не хранится. Работы создаются через сервисы, поэтому инварианты (неизменяемость попыток, снапшоты, история событий) соблюдаются и в демо-данных.

Необязательные инструменты браузерной проверки:

```bash
npm ci --ignore-scripts
python -m playwright install chromium
RUN_BROWSER_TESTS=1 python manage.py test lms.tests.test_browser --settings=core.test_settings
```

Node/axe-core используются только для тестов; frontend build и Node в production не нужны.

### Библиотека контента для преподавателя

Три уровня заготовок — по числу уровней иерархии курса (всё в `lms/library.py`, поэтому контент читается в ревью и версионируется вместе с кодом):

- **Шаблоны заданий** — в форме «Новое задание»: 19 заготовок — Fill in the Blanks, Key Word Transformation, Find & Correct Mistakes, Essay with Rubric, Listening & Dictation, Speaking Response, Reading Comprehension, Vocabulary Set, автопроверяемый тест, Sentence Builder, Sort into Columns, Word from Letters, Mini-project, Practical Email, Translation in Context, Role-play Dialogue, Collocations Sprint, Picture Story и Learning Reflection. Клик подставляет заголовок, условия, тип сдачи, максимум баллов и навыки; подстановка работает скриптом, без JavaScript форма остаётся обычной.
- **Готовые формулировки блоков и тем** — в формах блока и темы: 20 вариантов блоков с уровнем CEFR и 38 тем с описанием, от A1 до C1 и от повседневного английского до customer support и media literacy.
- **Наборы курсов** (`/teacher/library/`) — 11 готовых наборов: General English A2, General English B1–B2, ОГЭ/ЕГЭ, IELTS Academic, English for Kids, English for Teens, Business English, Travel, Movie Time, IT English и Happy Learning. Внутри — блоки → темы → задания, вопросы тестов и карточки тренажёра. Импорт создаёт задания **черновиками**: преподаватель проверяет формулировки и публикует нужное. Повторный импорт добавляет только недостающее — существующие блоки, темы и задания не перезаписываются.
- **Шаблоны наборов карточек** — на странице карточек задания-тренажёра: 14 готовых наборов по темам и уровням (A1–C1). Клик подставляет название и описание, карточки создаются при сохранении; шаблон можно подставить в массовый импорт для правок или добавить сразу. Карточки — не отдельная сущность, а **разновидность задания** (`assignment_type=flashcards`): такое задание живёт в теме рядом с остальными, ученик открывает его и тренируется, преподаватель видит его на карте курса.

Ссылка на библиотеку есть на карте курса (в шапке, в панели «Добавить» и в пустом состоянии).

### ИИ-помощник преподавателя (`/teacher/ai/`)

Файл или текст превращается в структуру курса: блок → темы → задания → вопросы теста → карточки. Логика живёт в `lms/ai.py`, интерфейс — в `lms/views_ai.py` и шаблоне `lms/teacher_ai.html`.

- **Локальная модель вместо облака.** Разбор выполняет модель на вашем сервере: **Ollama** (по умолчанию `qwen3-vl:8b`, `http://localhost:11434/v1`) или **LM Studio** (`http://localhost:1234/v1`). Ключей, аккаунтов и оплаты нет — как и передачи материалов наружу. Облачные адаптеры (Gemini, GigaChat, Yandex, шлюзы) удалены: им нужны ключ и квота, а Gemini API из России недоступен без VPN.
- **Фото и документы.** Vision-модель читает снимок страницы учебника (PNG/JPG/WEBP/GIF/BMP уходят в модель как изображение), а Word, Excel, PDF, TXT/MD/CSV разбираются офлайн через `zipfile` и встроенные парсеры. Видео и аудио локальная модель не читает — помощник честно пишет об этом в отчёте, а не молчит.
- **Офлайн-режим как страховка.** Пока модель не запущена (`LMS_AI_LOCAL=1` не выставлен), помощник не выключается: он раскладывает текст по структуре эвристиками. Выключить целиком — `LMS_AI_ENABLED=0`.
- **Свой шлюз — одна переменная.** Любое незнакомое имя в `LMS_AI_PROVIDER` считается OpenAI-совместимым: задайте `LMS_AI_ENDPOINT` и `LMS_AI_API_KEY`, код менять не нужно. Настройки на площадке проверяются командами `python manage.py ai_check` (без сети) и `python manage.py ai_check --live` (один пробный запрос к модели).
**Почему только локально.** Требование простое: помощник должен быть бесплатным, работать из России без VPN и читать фото. Облачные варианты этому не отвечают: Gemini API недоступен из РФ, у GigaChat и Yandex действуют квоты и тарифы, а материалы преподавателя уходили бы третьей стороне. Локальная модель избавляет от всего этого, поэтому в поставке остались Ollama, LM Studio и свой OpenAI-совместимый шлюз. Модели, требования к железу, установка и переменные — в [docs/AI_PROVIDERS.md](docs/AI_PROVIDERS.md) и `.env.production.example`. Точки входа: кнопка «ИИ-помощник» в шапке карты курса, ссылка в меню и подсказки в формах блока, темы и задания (там же можно сразу выбрать существующую тему как получателя).

Поддерживаемый формат текста для офлайн-разбора: `#` — блок, `##` — тема, `###` — задание (можно пометить тип: `[quiz]`, `[карточки]`), `?` — вопрос, `*` — верный вариант, `-` — неверный вариант, строки с `|` — карточки «слово | перевод | пример». Без заголовков материал становится одной темой.

На карте курса есть отдельная папка **«Архив»** и два варианта удаления. **Архивирование** блока, темы или задания скрывает его от учеников, но сохраняет сдачи и оценки; восстановление доступно с подтверждением. **Удаление навсегда** доступно и для целого блока, и для темы: кнопка раскрывает панель «Удалить блок целиком», и вместе с блоком уходят все его темы, задания, вопросы тестов и карточки. Требуется подтверждение. Если в поддереве есть сдачи учеников, удаление отклоняется с подсказкой — такие ветки уходят в архив, чтобы не потерять оценки и историю попыток.

В разделе **«Ученики»** преподаватель видит всех активных учеников единого учебного пространства и может нажать «Открыть как ученик»: приложение временно показывает интерфейс выбранного ученика, а верхний баннер всегда возвращает в режим преподавателя. Пароль ученика не меняется и права не выдаются навсегда; действие доступно только через POST с CSRF-защитой.

## Интерфейс и язык

- **Переключатель RU|ENG в шапке.** По умолчанию русский. Английский переводит только названия меню и функциональных действий (навигация, кнопки, хлебные крошки); учебные тексты, шаблоны заданий и примеры остаются английскими в любом режиме. Выбор хранится в cookie год и переключается ссылкой `?lang=eng` — параметр подхватывается без редиректа.
- **Язык курса.** Словарь переводов лежит в `lms/ui_text.py` (ключ — русская подпись, поэтому шаблон читается как обычный текст, а неизвестная строка просто остаётся как есть). В шаблонах подписи меню и действий оборачиваются тегом `{% t "Консоль" %}`, строка ниже по контексту — на английском.
- **Редактор «Условия задания».** Поле описания в форме задания разворачивается кнопкой «Развернуть» в большой редактор (до 62 vh, не на весь экран) с заметным фокусом и подсказкой; кнопка «Вернуть прежний размер» (или Esc) складывает его обратно.
- **Материалы перетаскиванием.** Любое поле файла превращается в дропзону: файл можно перетащить мышью или выбрать с диска, до отправки видны имя и размер, формат и лимит проверяются сразу, есть кнопка «Убрать файл». Без JavaScript поле остаётся обычным `input[type=file]`.
- **Аналитика в XLSX.** Журнал выгружается книгой Excel (`journal.xlsx`): закреплённая шапка, автофильтр, жирные заголовки, разумная ширина колонок, кириллица без «мастера импорта». Файл собирается встроенным писателем `lms/xlsx.py` (стандартные `zipfile` и XML) — новые зависимости не нужны.
- **Енот в шапке.** В шапке бежит мордочка енота в шарфе: бежит по опушке, переплывает озеро к книгам, читает их, возвращается домой и засыпает (мордочки `raccoon-face.svg` / `raccoon-sleep.svg`, цикл 56 с, `lms/static/lms/js/raccoon_scene.js`). При `prefers-reduced-motion` сцена статична, на узких экранах скрывается.

## Роли и права

- **Ученик** (`Profile.role=student`): все активные задания единого учебного пространства; только собственные ответы и файлы.
- **Преподаватель** (`Profile.role=teacher`): все работы этого учебного пространства, проверка и архив. Административные права автоматически не выдаются.
- **Администратор**: superuser создаёт пользователей и учебные материалы; профиль superuser создаётся как teacher. `is_staff` сам по себе больше не превращает пользователя в преподавателя.
- Django Admin принимает нового пользователя вместе с заполненным профилем. `auth.change_user`/управление группами выдавайте только доверенным администраторам: это привилегированные разрешения Django.
- Сдачи, проверки и события в Admin доступны только для просмотра. Ссылки ведут в интерфейс проверки с валидацией и контролем версии.
- Ученики могут менять свой пароль. Самостоятельный email-reset и MFA не подключены; восстановление — через администратора после проверки личности, MFA рекомендуется на уровне доверенного IdP/доступа администраторов.

**Это не мультитенантная система.** Независимые школы/клиенты должны использовать отдельные развёртывания. Изоляция групп и назначение заданий конкретным ученикам — отдельные продуктовые функции, не подразумеваемые текущей моделью.

## Попытки и проверки

Каждая отправка создаёт новый `Submission` с увеличенным `version`. Старый ответ, файл, время и feedback не перезаписываются. Максимум баллов и дедлайн фиксируются на момент отправки. Поздние ответы разрешены и помечаются; попытки ограничены частотой отправки и файловой квотой.

Преподаватель проверяет только последнюю попытку. Устаревшая форма ученика/преподавателя возвращает **409**, а не затирает данные. Параллельные операции сериализуются блокировкой строки ученика в PostgreSQL; проверка и событие сохраняются в одной транзакции. Два преподавателя не могут незаметно перезаписать решение друг друга. Каждая коррекция оставляет событие с автором, решением, оценкой и комментарием.

Каталог, очередь и история имеют пагинацию. В очереди есть фильтры «На проверке», «Ожидают доработки», «Проверенные» и «Все последние попытки».

## Файлы и ограничения

Все `.url` файлов ведут на авторизованный `/files/…`. Старый публичный `/media/` отсутствует **в обоих режимах DEBUG**. Не настраивайте public alias к private-media в Nginx, CDN или облачном bucket.

Загрузка ограничена размером и квотой; проверяются расширения, сигнатуры, структура ZIP-контейнера и реальное аудио через Mutagen. TXT — UTF-8. Архивы не распаковываются; ZIP64 и чрезмерные каталоги отвергаются. Скачивание всегда attachment, octet-stream, `nosniff`, `private, no-store`.

Проверка формата **не является антивирусом**. Для среды с недоверенными внешними загрузками настройте антивирус/карантин хранилища и безопасное открытие документов на рабочих местах. Не включайте выполнение кода в каталоге файлов.

| Переменная | По умолчанию |
|---|---:|
| `LMS_MAX_FILE_BYTES` | 20 MiB на файл/совокупность файлов запроса |
| `LMS_STUDENT_QUOTA_BYTES` | 200 MiB на ученика, включая историю; общий файл считается один раз |
| `LMS_SUBMISSIONS_PER_HOUR` | 30 отправок на ученика в час |
| `LMS_PAGE_SIZE` | 25 |
| `DJANGO_LOGIN_FAILURE_LIMIT` | 5 ошибок для пары учётная запись + IP |
| `DJANGO_LOGIN_COOLOFF_MINUTES` | 15 минут |

Ограничение входа работает через общую БД django-axes, включая Django Admin. Новая ошибка во время блокировки не продлевает её бесконечно. См. политику доверенных прокси в [инструкции развёртывания](docs/DEPLOYMENT.md).

Заменённые **материалы задания** удаляются после commit, если ссылок больше нет. Файлы **старых попыток** намеренно сохраняются как история; при удалении записей удаляются только больше нигде не используемые файлы. Непривязанные файлы после сбоев обнаруживает `cleanup_orphan_files` (по умолчанию dry-run с выдержкой 24 часа).

## Проверки

```bash
python manage.py test --settings=core.test_settings
coverage run manage.py test --settings=core.test_settings
coverage report
ruff check .
ruff format --check .
bandit -q -r core lms manage.py -x lms/tests,core/test_settings.py
python manage.py makemigrations --check --dry-run --settings=core.test_settings
pip-audit -r requirements.txt
```

`core.test_settings` всегда использует отдельную тестовую БД, временные файлы и тестовый hasher; не берёт production `DATABASE_URL`. Для PostgreSQL:

```bash
TEST_DATABASE_URL=postgres://USER:PASSWORD@HOST:5432/lms_test \
  python manage.py test --settings=core.test_settings
```

Пользователю тестовой БД нужно право `CREATEDB`; **не используйте production-сервер**. Проверки реальных параллельных транзакций выполняются только на PostgreSQL. Браузерный набор включается отдельно через `RUN_BROWSER_TESTS=1`.

CI проверяет SQLite и PostgreSQL на Python 3.12, гонки, миграцию старых данных, покрытие (порог 80%), Ruff, Bandit, зависимости, deployment settings, браузерный процесс с axe и Docker build/non-root smoke test. Требуйте успешных jobs в branch protection — сам файл workflow не включает защиту ветки автоматически.

## Зависимости

`requirements.in` / `requirements-dev.in` — диапазоны поддерживаемых версий. `.txt` — полные закреплённые наборы с хешами. Обновлять в изолированной среде Python 3.12:

```bash
pip-compile --upgrade --generate-hashes --no-emit-index-url --no-emit-trusted-host -o requirements.txt requirements.in
pip-compile --upgrade --generate-hashes --allow-unsafe --no-emit-index-url --no-emit-trusted-host -o requirements-dev.txt requirements-dev.in
# Затем весь набор CI, включая Docker, PostgreSQL и pip-audit.
```

Dependabot настроен для pip, npm, Docker и GitHub Actions. Базовые образы и actions закреплены digest/SHA; обновления должны проходить проверку, а не применяться вслепую.

## Production и обновление существующей установки

**Dockerfile называется `Dockerfile`, без `.txt`:** обычный `docker build -t english-lms .` работает без `-f`.
